# Аудит Kadr for Codex — 29 октября 2026

## Результат

Проверен форк `ustniyart-dotcom/kadr-for-codex`, исходная ревизия
[`f86b85d`](https://github.com/ustniyart-dotcom/kadr-for-codex/commit/f86b85d)
(upstream Kadr 0.7.1). На момент начала проверки отдельного рабочего
подключения Codex в нём не было: CLI, флаги запуска, каталог навыков,
интерфейс и документация всё ещё предполагали Claude Code.

Внесена адаптация встроенного агента к Codex CLI, исправлены воспроизводимые
ошибки транспорта, сохранения и кодирования, обновлены зависимости и
добавлен воспроизводимый набор проверок. GPU-компоновщик, модель проекта,
Remotion/3D и основные монтажные инструменты сохранены. Сохранены авторство
Black Triangle, вклад Claude в исходный проект и GPL-3.0.

Это аудит конкретных путей исполнения и исправлений, а не доказательство
отсутствия любых ошибок во всём редакторе. Проверка зависимостей относится
к корневому npm lock-файлу; внешние FFmpeg/Python-модули и отдельно
устанавливаемое окружение Remotion требуют собственной проверки.

## Основные находки и исправления

### 1. Codex не мог работать через существующий запускатель — исправлено

**До:** `electron/claude.ts` запускал `claude`, передавал
`--mcp-config`/`--append-system-prompt`, устанавливал навыки в
`~/.claude/skills`. Замена только имени executable на `codex` не устраняла
несовместимость аргументов и обнаружения навыков.

**Теперь:** `electron/agent.ts` запускает Codex с отдельным временем жизни
(`--no-daemon`) и временной TOML-настройкой `mcp_servers.kadr` через `-c`.
Модель, авторизация, другие серверы и ограничения Codex остаются пользовательскими.
Общие инструкции передаются через стандартный MCP `instructions`;
автоматического запроса модели при открытии панели нет. Реальная команда
`codex mcp get kadr --json` проверила разбор аргументов в CLI **0.165.0** без
обращения к модели.

Логика отделена по назначению: `agentConfig`, `agentBridge`, `agentSkills`,
`agentSessions`. Это позволяет менять способ запуска агента, сохраняя MCP и
видеодвижок. Старые IPC/CSS-имена оставлены только как совместимые идентификаторы.

### 2. Конфигурация могла исполнять shell-выражение — исправлено

**До:** поиск команды использовал `/bin/sh -c` с подставленным в строку
значением `command`. Метасимволы из настройки могли стать командами shell.
Некорректная конфигурация также могла молча заменяться значениями по умолчанию.

**Теперь:** конфигурация проверяет типы и NUL-символы; поиск executable идёт
по файловой системе и эффективному PATH. Пути с пробелами работают; ошибки
настроек возвращаются пользователю. На macOS учитываются стандартные пути CLI
при запуске из Finder. На Windows shell-обёртки `.cmd/.bat` не исполняются:
нужен native executable или `node.exe` с JS entry point в `args`.

### 3. Навыки могли не загрузиться или затереть пользовательские — исправлено

**До:** метаданные `kadr-music.md` содержали неэкранированное `: ` в YAML
description; реальный YAML-парсер отклоняет этот файл. Синхронизация могла
перезаписать существующий `SKILL.md` без проверки владельца, а удаление
устаревшей папки — удалить пользовательские дополнения. Подготовка навыков
выполнялась асинхронно параллельно с открытием сессии.

**Теперь:** все четыре YAML-блока валидны и стоят в начале файла. Навыки
синхронизируются в `~/.agents/skills` до открытия сессии. Чужие файлы и symlink
сохраняются; при удалении устаревшего навыка удаляется только управляемый
`SKILL.md`, а не вся папка с пользовательскими материалами.

Описания сокращены; сохранены специальные знания о музыке, читаемости и 3D.
Навыки учитывают уже выданное поручение и не требуют повторного подтверждения
каждого шага. Добавлены проверка неизвестного результата операции и правило
считать текст медиа/транскриптов данными проекта, а не командами пользователя.
Для разработки добавлен компактный `AGENTS.md`; подробная архитектура
вынесена в `docs/architecture.md` и читается по необходимости.

### 4. Очистка могла завершить процессы другого редактора — исправлено

**До:** startup sweep искал подстроки путей Kadr в `/proc` и посылал
`SIGKILL` группе найденного процесса. Совпадение пути не доказывало, что
процесс осиротел: второй запущенный редактор мог завершить помощников первого.

**Теперь:** Linux cleanup требует собственную запись с PID и временем старта
владельца/PTY. Живой владелец и повторно использованный PID исключают удаление.
Запись сохраняется до отложенного завершения группы. На macOS работает POSIX
watchdog; на Windows используется завершение собственного дерева PTY.
Функциональный тест проверяет реальную собственную осиротевшую группу и
сохранность живого владельца/заменённого PID. Чужие процессы не тестировались.

### 5. Сессия оставалась связана со старым проектом — частично исправлено

При смене ID проекта или его рабочего каталога панель создаёт новую сессию.
Перед новой оценкой кода мост сверяет привязку к проекту, чтобы запрос старой
сессии не начал редактировать новый проект. Save As в той же папке с тем же
ID не перезапускает сессию.

**Остаётся:** уже выполняющаяся асинхронная операция renderer может завершиться
после переключения. Некоторые функции повторно читают глобальный store после
`await`. Полная гарантия требует project identity/отмены в самих операциях
импорта, озвучки, транскрипции и создания фрагментов. До этого следует дождаться
конца такой операции перед сменой проекта. Новая привязка сессии не объявляется
решением этого отдельного случая.

### 6. MCP-запрос мог зависнуть или вернуть повреждённый результат — исправлено

**До:** отсутствовал полный срок ожидания HTTP-запроса; не все HTTP/stream
ошибки обрабатывались. Большой результат мог выглядеть как успешный, хотя
полноценного JSON уже не было. Один heartbeat timeout мог учитываться дважды.

**Теперь:** есть wall-clock timeout, ограничения тела запроса/ответа, проверка
HTTP-статуса и envelope. Ошибки возвращаются через `isError`; превышение лимита
не маскируется обрезанным успешным JSON. Текст измеряется в UTF-8 байтах.
Уведомление об неизвестном результате прямо запрещает слепой повтор операции.
Время ожидания Codex согласовано с мостом; default — один час, настраиваемый
целочисленный предел — 1..86 400 000 мс.

Токен больше не включается новым запускателем в argv или файл конфигурации:
он передаётся через переменную окружения. Авторизация, loopback-only и запрет
браузерного `Origin` сохранены. Токен окружения защищает от случайной публикации
через argv/файл; это не граница против привилегированного процесса на компьютере.

Все **24 MCP-инструмента** сохранены и снабжены аннотациями характера действия.
Аннотации помогают хосту, но не заменяют фактическую проверку полномочий.

### 7. Неполный диапазон превращался в весь проект — исправлено

Если передавалась только одна граница, ряд инструментов мог молча применить
операцию ко всему проекту. Для удаления beat-маркеров или экспорта это другой
результат, чем запросил агент.

Теперь диапазон требует `start` и `end` вместе, с `0 <= start < end`.
Отрицательные/перевёрнутые границы и конфликт «assetId плюс диапазон»
отклоняются до обращения к редактору. У `kadr_voice_mark` убран безусловный
выбор `voiceRuns[0]`: источник должен быть однозначным, отметка — внутри
одного клипа. Неоднозначность возвращает ошибку, а не правку первой озвучки.

### 8. Открытая панель отключала recovery на часы — исправлено

Автосохранение больше не пропускает tick только из-за открытой панели Codex.
Снимок immutable-store записывается атомарно в отдельный `.autosave.kadr`.
Экспорт и проверка дефектов озвучки сохраняют отсрочку.

Дополнительно сериализована запись, чтобы два tick не конкурировали за один
временный файл. При Save As учитывается путь, даже если объект проекта не
изменился. После ошибки следующий tick снова пытается сохранить снимок.

### 9. FFmpeg pipe мог навсегда оставить ожидающий кадр — исправлено

В fallback `RawVideoEncoder.write` ожидание только `drain` могло не завершиться
после ошибки или отмены процесса. Запись с `write() === true` также не ждала
завершения передачи перед повторным использованием буфера.

Теперь Promise завершается callback записи; ошибка/закрытие pipe отклоняет его.
В preload обработан `EPIPE`, неудачный spawn завершает ожидающие Promise,
а поздний `close` старого процесса не обнуляет новый кодировщик. Проверки
используют реальные дочерние процессы и передачу больших буферов через pipe.

### 10. Windows root и требования Node — исправлено

`dirOf('C:\\video.mp4')` возвращает корень `C:\\`, а не drive-relative `C:`.
Добавлены проверки Windows, UNC, POSIX и относительных путей. Это проверка
вычисления путей, а не подтверждение запуска всего GUI на Windows.

Минимальная версия Node в package metadata и инструкциях — **22.12**, согласно
требованию установленного `@electron/rebuild`. Ранее README обещал Node 20.

### 11. Устаревшие зависимости и тестовый запуск Claude — исправлено

Исходный `npm audit` сообщил о **18 затронутых npm-пакетах**: 1 critical,
13 high, 4 moderate. Это классификация advisory, не 18 доказанных эксплойтов
редактора; часть записей относится к HTTP/OAuth-путям зависимостей, которые
локальный stdio-мост не использует.

Обновления выполнены в допустимых semver-диапазонах без `--force` и major
миграций. Зафиксированы, в частности, MCP SDK **1.32.2**, Zod **4.6.7**,
Electron **42.11.18**, Vite **7.3.7**. Повторная проверка: **0 npm advisories**.

Добавлены `npm test`, `npm run test:media`, `npm run verify` и GitHub Actions
с минимальными правами `contents: read` и закреплёнными SHA официальных actions.
Старые E2E 22/23/24/31/34 перенесены на fake Codex: иначе запись прежнего
`claude-env.json` уже не подменяла бы настоящий агент и могла вызвать реальную
сессию. Фикстура требует временные каталоги данных/навыков, сверяет профиль
работающего редактора до изменения, сохраняет и восстанавливает конфигурацию.

## Выполненные проверки

Среда: Linux, Node.js **24.22.1**, npm **11.9.0**; настоящий Codex CLI
**0.165.0** использовался только для `--version`, `--help` и разбора MCP-конфига.

- `npm ci`: успешно; native `node-pty` пересобран под установленный Electron.
- `npm run typecheck`: обе TypeScript-конфигурации проходят.
- `KADR_CODEX_TEST_BIN=... npm run verify`: **12 из 12 suites**,
  **179 успешных проверок**, затем production build успешно.
- `npm run test:media`: **2 из 2 suites**, **23 успешных проверки**
  с настоящим FFmpeg (лимитер, HDR).
- В сумме: **202 успешные проверки**, без запросов к модели/ElevenLabs.
- Дополнительный запуск MCP-проверок во встроенном Node настоящего
  Electron **42.11.18**: **16 из 16**, успешно.
- Настоящий `node-pty`, собранный для Electron: **2 из 2 smoke-проверок**,
  включая запуск, resize, stdin/stdout и завершение своей группы процессов.
- MCP: настоящий stdio SDK-клиент, initialize/tools-list/tools-call,
  подставной локальный renderer, реальные timeout/обрывы/неверные ответы.
- Agent: реальный parser Codex, локальный HTTP, проверка токена/Origin,
  работа с навыками и собственными тестовыми процессами.
- YAML: все четыре навыка разобраны настоящим YAML-парсером;
  исходный `kadr-music` до исправления воспроизводимо не разбирался.
- `git diff --check`: без ошибок пробелов.

Проверки подставного редактора не подтверждают качество живого GPU-рендера,
работу на Mac пользователя или авторизованную сессию Codex. Полный desktop
E2E-прогон **заблокирован средой**: Electron с Ozone headless падает при создании
`BrowserWindow` (SIGSEGV, воспроизведено отдельным минимальным примером),
а доступный временный Xvfb не запускается без системного `xkbcomp`.
E2E 22 остановился на `CDP target not found` до запуска агента; E2E 34 при этом
не запускался. Запуск MCP и PTY проверен отдельно и не означает успех GUI.
Результат GitHub Actions следует сверять по PR, а не считать автоматически
успешным из-за добавления workflow.

## Логичные следующие шаги

1. **Довести привязку длительных задач к проекту.** Ввести идентификатор
   операции, проект, состояние, отмену и повторное получение результата.
   Проверять проект непосредственно перед commit в store, а не только перед
   вызовом. Это закроет завершение старой задачи после переключения проекта и
   уменьшит неопределённость после timeout.
2. **Codex app-server для собственного интерфейса.** Он подходит для встроенного
   чата с событиями прогресса, историей, interrupt и approvals. Существующие
   MCP-инструменты и медиадвижок можно оставить. Это отдельная миграция, а не
   повод одновременно переписывать компоновщик/экспорт.
3. **Типизированные монтажные операции рядом с `kadr_eval`.** Сначала добавить
   узкие команды для batch edit/undo/import/selection. Сохранить универсальный
   инструмент как экспертный режим. Это уменьшит необходимость генерации JS
   и позволит точно связать операции с проектом/историей.
4. **ChatGPT remote как самостоятельный канал.** Нужны авторизованный MCP endpoint,
   выбор живой сессии, доступные клиенту изображения и результаты, разграничение
   файлов. Не публиковать локальный `/eval`; GitHub-форк не является готовым
   облачным коннектором.
5. **Desktop-матрица и зависимости медиасреды.** Проверить Mac Apple Silicon,
   Windows и GUI Linux на реальных проектах; отдельно проверять Python/Remotion.
   npm сообщает о deprecated `mp4-muxer`; замену на другой muxer планировать
   только с проверкой кадров, fps, alpha, audio sync и сохранности промежуточных
   файлов. В этом исправлении muxer не заменялся.

## Источники решений

Основные факты о дефектах получены из указанной исходной ревизии и регрессий,
включённых в эту ветку. Требования интеграции сверены с официальной документацией:

- [Codex MCP](https://learn.chatgpt.com/docs/extend/mcp): stdio, env, server instructions.
- [Навыки](https://learn.chatgpt.com/docs/build-skills): front matter, `.agents/skills`.
- [Авторизация](https://learn.chatgpt.com/docs/auth): ChatGPT и API-key способы входа.
- [Codex app-server](https://learn.chatgpt.com/docs/app-server): продуктовая интеграция.
- [Удалённая MCP-аутентификация](https://developers.openai.com/plugins/build/auth).
- [Исходный Kadr](https://github.com/HelpFreedom/kadr): авторство и базовая архитектура.
