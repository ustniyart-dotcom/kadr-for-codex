# Kadr: работа с Codex и ChatGPT

В этом форке встроенная панель запускает **Codex CLI** и подключает к нему
открытый проект через MCP. Сам монтаж, GPU-превью, Remotion, обработка звука
и форматы проектов остаются частью Kadr.

## Запуск

Нужны Node.js **22.12 или новее** (проверено на Node.js 24), FFmpeg/FFprobe
в PATH и установленный Codex CLI. Требование Node.js связано в том числе с
`@electron/rebuild`, который пересобирает нативный `node-pty`.

```bash
git clone https://github.com/ustniyart-dotcom/kadr-for-codex.git
cd kadr-for-codex
npm ci
npm run dev
```

Сначала проверьте `codex --version` и выполните обычный `codex login` в своём
терминале, если ещё не входили. Codex поддерживает вход через ChatGPT или
API-ключ; Kadr использует уже настроенный вариант. Отдельный OpenAI API-ключ
в настройках Kadr не нужен при входе Codex через ChatGPT. Доступ к моделям и
лимиты определяются вашей учётной записью и настройками Codex, а не Kadr.

В Kadr откройте или сохраните проект и нажмите **Codex** в верхней панели.
Открытие панели само по себе не отправляет запрос модели. Например:

> Прочитай текущий проект. Покажи, какие клипы и звуковые дорожки в нём есть,
> и предложи, где сократить паузы. Пока ничего не меняй.

Затем можно поручить правку:

> Вырежи паузы из указанного фрагмента, сохрани синхрон звука и изображения,
> проверь начало и конец каждого стыка. Экспорт пока не нужен.

Или сразу запросить результат с экспортом:

> Собери из выбранных клипов ролик на 30 секунд, добавь субтитры, проверь их
> читаемость и экспортируй MP4 в папку проекта.

## Как подключается агент

Kadr запускает самостоятельную интерактивную сессию через `--no-daemon` и
передаёт временную конфигурацию `mcp_servers.kadr` параметром `-c`.
Поддержка этих параметров проверена на **Codex CLI 0.165.0**. Нужна версия с
`--no-daemon`; если CLI сообщает о неизвестном параметре, обновите Codex.

Это сохраняет обычные модель, авторизацию, остальные MCP-серверы, `CODEX_HOME`
и правила разрешений Codex. Kadr не записывает глобальный `config.toml` и не
включает обход sandbox/подтверждений. Существующая запись с именем `kadr`
заменяется только внутри этой сессии, чтобы URL старого сервера не смешивался
с новым stdio-подключением.

Мост слушает только `127.0.0.1` на случайном порту. Секрет создаётся заново
для сессии и передаётся MCP-процессу через `KADR_BRIDGE_TOKEN`, без сохранения
в проекте и без включения в аргументы процесса. Запросы с браузерным `Origin`
отклоняются. MCP-сервер сообщает рабочий цикл и назначение инструментов через
стандартное поле `instructions` при инициализации.

У несохранённого проекта рабочий каталог ограничен `<userData>/agent-workspace`;
у сохранённого — папкой проекта. Закрытие панели завершает её сессию. При смене проекта или его
рабочего каталога панель создаёт новую сессию вместо продолжения старого разговора. Эта защита
отклоняет новые запросы старой сессии. Уже начатая асинхронная операция
редактора ещё может завершиться: полной отмены всех фоновых операций при
переключении здесь нет. Дождитесь её окончания перед сменой проекта.

## Настройки конкретного компьютера

Необязательный файл **`codex-env.json`** находится в каталоге данных Kadr:

- Linux: `~/.config/kadr/codex-env.json` при стандартном XDG-настройке.
- macOS: `~/Library/Application Support/kadr/codex-env.json`.
- Windows: `%APPDATA%/kadr/codex-env.json`.
- При заданном `KADR_USER_DATA`: в указанном каталоге.

Пример для прокси:

```json
{
  "env": {
    "HTTPS_PROXY": "http://127.0.0.1:1080",
    "NO_PROXY": "127.0.0.1,localhost"
  }
}
```

Если приложение, запущенное из Finder, не видит CLI:

```json
{
  "command": "/opt/homebrew/bin/codex",
  "args": ["--no-alt-screen"]
}
```

`command` — один исполняемый файл, без shell-выражений. `args` — дополнительные
аргументы Codex, соединение с Kadr добавляется к ним автоматически. Для
командного переопределения также есть `KADR_CODEX_CMD`. На Windows указывайте
нативный `codex.exe` либо `node.exe` с путём к JS-точке входа Codex первым
элементом `args`; `.cmd`/`.bat` требуют shell и автоматически не запускаются.
Это ограничение не подтверждает работоспособность всего редактора на Windows:
полный GUI-прогон на этой платформе ещё нужен.

Старые `claude-env.json`, `claude-mcp.json` и `KADR_CLAUDE_CMD` не выбирают
агента в этом форке. Перенесите нужные PATH/proxy-настройки в `codex-env.json`,
а дополнительные MCP-серверы оставьте в обычной конфигурации Codex.
Не копируйте Claude-специфичные аргументы: их интерфейс отличается.

## Навыки и рабочие файлы

Перед стартом сессии Kadr синхронизирует четыре составных навыка в
`~/.agents/skills`: `kadr-editor`, `kadr-music`, `kadr-motion`, `kadr-3d`.
В пользовательских папках изменяются только файлы с меткой `managed by Kadr`;
чужие навыки, символьные ссылки и дополнительные файлы сохраняются.
При совпадении имени с пользовательским навыком Kadr оставляет его и
записывает предупреждение. Исходники навыков — `electron/skills/*.md`.

Базовый цикл: прочитать `kadr_state`, выполнить согласованную правку, проверить
тайминги и кадры через `kadr_snapshot`/`kadr_sheet`. Снимки возвращаются как
пути на компьютере редактора; агенту нужен доступ к этим файлам и инструмент
просмотра изображений. Remotion-фрагменты редактируются обычными файловыми
инструментами Codex и обновляют превью без полного экспорта.

Открытая панель больше не выключает автосохранение. Изменённый проект
сохраняется в отдельный `.autosave.kadr` раз в пять минут; экспорт и проверка
озвучки продолжают временно откладывать запись.

## Длительные операции и ошибки

Экспорт, распознавание и проверка озвучки могут работать долго. По умолчанию
у мостового запроса есть предел в один час; `KADR_BRIDGE_TIMEOUT_MS` позволяет
задать целое число миллисекунд от 1 до 86 400 000, и timeout инструмента Codex согласуется
с ним. Это предел ожидания ответа, а не гарантированная отмена рендера.

После потери связи или timeout результат изменения может быть неизвестен.
Сначала перечитайте проект и журнал, затем решайте, нужен ли повтор. Повтор
вставки клипа или платной озвучки вслепую может создать дубликат или лишнее
списание. Для диапазона передавайте обе границы `start` и `end`; одна граница
больше не превращается молча в операцию над всем проектом.

## Где здесь ChatGPT

**Вход Codex через аккаунт ChatGPT** уже подходит для встроенной панели.
Это локальная работа агента рядом с редактором.

**Чат ChatGPT в браузере** не получает доступ к компьютеру от одного наличия
GitHub-репозитория или локального stdio-сервера. В этом изменении не развёрнут
удалённый MCP-коннектор и не выпущен устанавливаемый облачный плагин. Для такого
сценария нужны отдельно подключённая среда исполнения, авторизованный канал
к редактору, выбор проекта/сессии и выдача изображений/результатов клиенту.
Сырой `/eval` нельзя публиковать в Интернет: у него доступ к файлам и изменениям
проекта. Его loopback-секрет — механизм локальной сессии, не OAuth пользователей.

Для более тесного интерфейса внутри Kadr следующий разумный шаг —
**Codex app-server**: он предоставляет структурированные события, историю,
прерывание и запросы подтверждения. Существующий слой MCP можно сохранить.
PTY-панель даёт рабочую основу сейчас; переход на app-server стоит делать
отдельно, с проверкой отмены, восстановления и привязки к проекту.

## Проверки

```bash
npm run verify
npm run test:media
```

Первая команда проверяет типы, переносимые регрессии и сборку. MCP-тесты
проходят реальный stdio-протокол с подставным редактором; они не обращаются к
модели. Вторая команда требует FFmpeg. Для CDP-тестов используйте пустой проект
и отдельные временные каталоги `KADR_USER_DATA` и `KADR_AGENT_SKILLS_DIR`,
одинаковые у приложения и теста. Второй путь изолирует запись навыков и
предназначен для теста с подставным CLI, а не для обычного обнаружения навыков Codex.
Пример для двух терминалов (используйте один и тот же созданный каталог):

```bash
# Терминал 1: новый пустой каталог теста
KADR_TEST_ROOT="$(mktemp -d)"
mkdir -p "$KADR_TEST_ROOT/profile" "$KADR_TEST_ROOT/skills"
KADR_USER_DATA="$KADR_TEST_ROOT/profile" KADR_AGENT_SKILLS_DIR="$KADR_TEST_ROOT/skills" \
  KADR_TTS_MOCK=1 npm run dev -- -- --remote-debugging-port=9777
```

Во втором терминале задайте `KADR_TEST_ROOT` тем же абсолютным путём:

```bash
KADR_USER_DATA="$KADR_TEST_ROOT/profile" KADR_AGENT_SKILLS_DIR="$KADR_TEST_ROOT/skills" \
  node scripts/e2e22.mjs
KADR_USER_DATA="$KADR_TEST_ROOT/profile" KADR_AGENT_SKILLS_DIR="$KADR_TEST_ROOT/skills" \
  KADR_E2E_AGENT_ONLY=1 node scripts/e2e34.mjs
```

Фикстура проверяет профиль работающего приложения до запуска агента. Она
использует подставной CLI; настоящая авторизация и модель для этих тестов не нужны.
